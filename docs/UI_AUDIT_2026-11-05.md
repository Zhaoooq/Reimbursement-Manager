## 1. 总体判断

**一句话结论：视觉语言已经统一到 Apple 浅色体系，但"令牌 — 组件 — 页面"三层中只有第一层真正确立，第二层靠 QSS 后置覆盖拼起来，第三层每个页面各写一套，导致一致性只能靠人工记忆维持。**

三条结构性判断：

**判断一：`base.qss` 已进入"重复定义 + 后置覆盖"阶段，是最该先处理的技术债。**
同一控件被定义 2–4 次：`#dashboardMissing` 4 次（460 / 1252 / 1322 / 1346 行）、`#attachmentCard:hover` 3 次（1145 / 1336）、`#successBadge` 2 次（516 / 1316）、`#materialRequirementBadge` 2 次（1089 / 1251）。更关键的是 1212 行起的 `iOS-12` 统一块整段覆盖了前面 952 行、756 行、1089 行定义的 Badge。后果是"改一处没效果"——这在后续每次小改动里都会重复付出代价。

**判断二：令牌体系只覆盖了颜色，间距、字号、组件尺寸全靠页面里写数字。**
`ThemeTokens`（theme.py:15-52）有 26 个颜色 + 5 个字号 + 3 个圆角，但没有 spacing、没有控件高度、没有表格行高。所以 `margin=14` 出现 22 次、`spacing=2/6/10/14` 混用、字号多出 15 和 20 两档。这不是审美问题，是"没有可引用的常量"。

**判断三：页面模板不统一。**
7 个页面各自搭 header（`QVBoxLayout` + `spacing 4`）、各自配表格（5 套 resize mode + 4 套对齐参数）、各自写空状态（4 处相似代码）。同一件事——"状态怎么显示"——现在有 4 种实现：纯文本（批次列表 2985）、QLabel 徽标（所有物品 1681）、QLabel 徽标（批次详情）、`setBackground` 整格染色（待补材料 1488）。

## 2. 问题清单

按严重程度排序。P0 = 影响可用性或产生误导，建议在动样式之前先修；P1 = 明显拉低质量；P2 = 打磨项。

### P0-1 待补材料页：物品名称列被挤成 22px，等于消失

- 位置：`main_window.py:1409-1415`
- 现象：第 0 列 `Stretch`，其余 5 列 `ResizeToContents`。长中文"缺少：实物照片、支付截图、发票、订单截图"把两列撑到 310px 和 268px，5 列合计 818px，840px 的视口只剩 **22px** 给物品名称。截图里"物品名称"表头和数据都看不到。
- 影响：这一页存在的唯一理由就是"哪个物品缺什么"，现在答不出前半句。**这是全软件最严重的视觉缺陷。**
- 修法：物品名称列改为 `Interactive` + 最小 160px，缺失列设 `Stretch` 且允许省略（`setTextElideMode(ElideRight)` + ToolTip 全文），或者直接把缺失材料从"一行长文本"改成"数量 + 首项"，完整清单进 ToolTip。

### P0-2 详情页不更新侧栏选中态

- 位置：`_open_batch_detail`（3248-3259）、`_open_item_detail_from_table`（2018-2029）、`_open_dashboard_item_detail`（3965-3971）
- 现象：三处都只 `pages.setCurrentIndex(...)`，没有同步 `navigation.setCurrentRow`。截图证据：在物品详情页时侧栏高亮的是"设置"或"首页"。
- 影响：用户失去"我在哪一层"的定位；返回后侧栏还会跳到别的分组。
- 修法：进详情页时把侧栏选中项固定到来源页（批次详情→报销批次，物品详情→所有物品/首页），并给详情页加一个"当前层级"标识。

### P0-3 批次详情同屏两个 Primary 实心按钮

- 位置：`main_window.py:3086-3095`（`+ 新增物品`，primaryButton）、`3157-3160`（`标记批次已提交`，primaryButton）
- 现象：两个实心蓝按钮分处页面上半区，权重完全相同。设计规范明确"一个视区只允许一个 Primary 实心按钮"。
- 影响：破坏"下一步做什么"的唯一指向；用户不知道哪个是主操作。
- 修法：`新增物品` 保持 Primary，工作流动作改 `quiet` 变体（白底蓝字），并按 PHASE5 §24 只在对应状态出现一个。

### P0-4 首页"已提交"统计数字没有样式

- 位置：`main_window.py:3752-3760` 传 `semantic="secondary"`；`base.qss:388-405` 只有 `accent / success / warning` 三个变体
- 现象：四张统计卡里三张数字有颜色，"已提交"是纯黑。截图可见明显不齐。
- 影响：四张同权统计卡视觉不齐，且暴露"属性拼错也没人发现"的机制问题。
- 修法：先决定语义——建议统计数字**全部使用 `primary_text`**，颜色只用在需要提示的那一张（待处理用 `warning_text`）。若保留多色，则在 QSS 补 `[semantic="secondary"]`，并同时用 `warning_text` / `success_text` 替代 `warning` / `success` 原色（见 P1-6 对比度问题）。

### P0-5 物品详情没有"编辑物品"入口（功能缺失）

- 位置：全文件搜索 `编辑` 仅命中 `TemplateEditorDialog`（615 行）；无 `EditItemDialog`，`_populate_item_detail` 只做展示
- 现象：物品的金额、日期、平台、商家、订单号创建后无法修改，只能删除重建（删除还要二次确认）。
- 影响：这是 `AGENTS.md` P0 功能清单里的"编辑报销物品"，当前缺失。操作效率问题比视觉问题更严重。
- 处置：**属于功能补齐，不属于 UI 改造**。建议单独立项，本轮不动。需要你确认是否排期。

### P0-6 批次详情"删除批次"始终可点

- 位置：`main_window.py:3237-3244`
- 现象：提示文字写"仅可删除没有物品的批次"，但按钮从未 `setEnabled(False)`。截图里批次有 1 个物品，删除按钮仍是可点的危险态。
- 影响：点击后才失败，属于"可预期的错误让用户去踩"。
- 修法：`item_count > 0` 时禁用，并把禁用理由写进按钮 ToolTip 或把提示文字改成"含 1 个物品，无法删除"。

### P0-7 键盘不可达（14 处）

- 位置：`main_window.py` 中 `setFocusPolicy(Qt.FocusPolicy.NoFocus)` 共 14 处，含 4 张主表格与全部返回/文字按钮（980、1398、1568、1606、1780、1841、3066、3188、3888、2445 等）
- 现象：表格无法用方向键浏览、无法 Enter 打开；返回链接、添加附件、查看详情都不是焦点可达元素。
- 影响：纯鼠标软件；高分辨率触控板/键盘用户操作效率低。同时 QSS 里没有任何 `QPushButton:focus` 规则，即使恢复焦点策略也看不见。
- 修法：分两步——先补 `:focus` 焦点环（1px accent + 1px 内缩，避免尺寸抖动），再逐页恢复焦点策略与 Enter 触发。

### P1-1 字号出现"编外两档"，层级关系被打乱

### P1-2 材料卡标题与页面区块标题同级

### P1-4 支付凭证区卡片套卡片 + 四处重复表达同一件事

- 位置：`main_window.py:2223-2252`；`base.qss:1017-1027`（`#mergedPaymentSection` 白卡内再套 `#mergeOrderSource` 灰卡）
- 现象：白卡里嵌两张灰卡，灰卡里再嵌附件卡，共三层底色；箭头文字 `↓\n最终支付截图`（2249）与结果卡标题 `最终支付截图`（2259）重复；`尚未生成最终支付截图`（2267）、`还缺订单截图。`（2299-2306）与两个"缺少…"徽标三处重复。

### P1-5 材料卡信息三重冗余，"必需"徽标变成噪音

- 位置：`main_window.py:2417-2451`
- 现象：每张卡同时有"实物照片 + **必需** + 1 个附件"（第一行）、"缺少材料"（第二行）、"可拖动一个或多个文件到此区域"（第三行）、"+ 添加附件"（第四行）。当 4 个材料全部必填时，4 个蓝色"必需"徽标只是重复。
- 影响：卡片 155px 高，其中 60% 是说明文字；同一句话重复 4 次。违反 `AGENTS.md` §17"避免不必要的次要标签和描述"。
- 修法：必需项不显示徽标，只对"选填"标灰字"选填"；拖动提示只在拖拽进入时出现；"添加附件"改成带边框的次级按钮（当前是无边框文本链接，点击区只有文字大小，与高频操作不匹配）。

### P1-6 统计数字用原色，白底对比度不足

- 位置：`base.qss:395-405`
- 现象：`warning #FF9F0A`、`success #34C759` 直接用于 28px 数字，白底对比度约 2.1:1。
- 影响：大字号文本的可用下限是 3:1，两项不达标；对低对比敏感用户和投影场景几乎不可读。令牌里本来就有 `warning_text #9A5B00`、`success_text #248A3D` 专用于文本。
- 修法：大数字一律用 `*_text` 系列，`*` 原色只用于图形/进度条填充。

### P1-7 金额：用蓝色 + 无千分位

- 位置：`base.qss:915-920`（`#itemDetailAmount` 用 `@ACCENT@`）；`main_window.py:3717-3718`（`_format_cents`）
- 现象：金额是页面右上角唯一蓝色元素，看起来像链接；`¥1280.50` 没有千分位，`PHASE3_5` §17 的示例是 `¥1,280.50`。另外负数会输出 `¥-1.00`（正确应为 `-¥1.00`）。
- 影响：金额是全软件第二重要的数据，蓝色会诱导点击，且与"可点击"语义冲突。
- 修法：金额改 `primary_text`；`_format_cents` 加千分位并处理负数。**注意**：现有测试只断言 `¥0.00 / ¥123.45 / ¥180.00`（均小于 1000），改千分位不会破坏断言。

### P1-8 物品详情元信息卡内容空洞、像输入框

- 位置：`main_window.py:1859-1883`；`base.qss:922-927`
- 现象：卡片固定 46px 高，5 个 label 中 3–4 个是空字符串仍占行高；当前数据只显示一行"所属批次：1"。白底 + 1px 描边 + 14px 圆角，观感像只读输入框。
- 影响：最重要的"这是哪个物品的什么单"信息被压缩成一行，同时留下无意义的空白。
- 修法：改成无边框的两行文本（`平台 · 日期` / `商家 · 订单号 · 批次`），空值统一 `—` 且不隐藏字段；或改成 2×2 的键值栅格，键用 13px 灰字。

### P1-9 设置页没有分组，四个卡片等权重

- 位置：`main_window.py:957-1064`；`base.qss:674-712`
- 现象：`数据与存储` / `数据库备份` / `恢复数据库` / `应用` 四个 17px 加粗标题并列，但前者是"分组"，中间两个是"动作"。同时首卡内边距 `16,14`（960 行）与其余三卡 `20,20`（991 / 1020 / 1053 行）不一致，截图里首卡明显更紧。
- 影响：`PHASE5` §27 要求"数据 / 应用"两组 Grouped Card，现在是 4 张平行卡，纵向占 609px 却只装了 5 行信息。
- 修法：两组分组标题（数据 / 应用）+ 组内行式布局：左侧标题 + 副说明，右侧动作按钮，行高 56，行间 1px 分隔线。恢复数据库单独放"危险"分区。

### P1-10 术语不一致：「合并支付截图」vs「最终支付截图」

- 位置：`main_window.py:2113`（详情页显示 `合并支付截图`）、`1509-1513`（待补材料页替换成 `最终支付截图`）、`2311`（去重提示"最终支付截图"）
- 现象：同一材料在待补材料页叫"最终支付截图"，在物品详情页叫"合并支付截图"。
- 影响：用户对不上号，尤其两页对照补齐材料时。
- 修法：展示层统一为"最终支付截图"（只改显示文本，不改业务枚举与导出文件名）。

### P1-11 模板列表表头居中，与其他表格不一致

- 位置：`main_window.py:1220-1244`（未调用 `_align_table_headers`）
- 现象：模板表沿用 Qt 默认表头对齐（居中），另外 4 张表都调用了 `_align_table_headers`（左对齐）。截图里"模板名称"居中、"材料"右对齐，与批次表/物品表的左对齐不同。
- 影响：切页时表头"跳动"。
- 修法：补调用 `_align_table_headers(self.template_table, right=(1,), center=(2,))`；顺便把第三列的 `›` 换成行尾图标位，避免空表头。

### P1-12 状态呈现有 4 种实现

- 位置：批次列表纯文本（2985）、所有物品 QLabel 徽标作 cellWidget（1681-1685）、批次详情 QLabel 徽标、待补材料整格 `setBackground`（1488-1494）
- 影响：同一状态在不同页颜色/形态不同；cellWidget 还带来"行 hover 时徽标格不变色"的断块。
- 修法：统一为一个 `StatusBadge` 工厂 + 表格内用 `QStyledItemDelegate` 绘制（避免 cellWidget 的 hover 断块），批次列表同步改徽标。**注意**：`tests/ui/test_main_window.py:807`、`538`、`545` 断言状态列是纯文本，改成徽标必须同步改测试（属允许范围，但要提前说明）。

### P1-13 侧栏图标是 16/32/128 位图，缩放到 18px

- 位置：`main_window.py:889-898`（`QStyle.StandardPixmap` 六个）
- 现象：系统位图按 18×18 绘制会重采样发糊；且图标自带颜色语义——"待补材料"用了 `SP_MessageBoxWarning` 黄色警告三角，"所有物品"用 `SP_FileIcon` 几乎看不见。选中态只能改文字色，图标不会跟着变色。
- 影响：侧栏是最高频的视觉锚点，现在 6 个图标风格不统一（文档/盒子/文件/警告/文件夹/齿轮），像拼凑。

### 4.4 QSS 结构规则（比令牌更重要）

1. **一个选择器只出现一次**。1212 行起的 `iOS-12` 统一块把前面所有 Badge/进度条定义覆盖掉，是最典型的反例。建议按"基础 → 布局 → 组件 → 页面"重排，组件层每个 `objectName` 只写一次。
2. **全局 `QWidget { background: @APP_BACKGROUND@ }`（第 2 行）要收回**。因为它，后续所有 Label 都得写 `background: transparent`（全文 30+ 处）。改成只给 `QMainWindow / QStackedWidget / 页面容器` 设底色。

4. **禁用态必须与次级态可区分**：现在 `QPushButton:disabled`（89-93）是灰底灰字，与 `QPushButton:hover`（80-83）同底色系，两者在截图里容易混；建议 disabled 用 `secondary_surface` + `tertiary_text` + `border-color: @SEPARATOR@` 三条同时生效。
5. **补 `#primaryButton[quiet="true"]:disabled`**：现在没有规则，quiet 按钮禁用时仍是蓝字，看起来可点。
