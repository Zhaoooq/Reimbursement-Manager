# Phase 2 基础界面设计

## 目标

提供一个可直接打开的 Windows 桌面窗口，让用户首先看见应用的信息结构，并能创建报销批次。该界面连接本地 SQLite 数据库，不使用演示假数据，也不实现附件上传或完整导出。

## 信息架构

窗口分为两栏：左侧为深色导航，包含“首页、报销批次、所有物品、待补材料、模板管理、设置”；右侧为浅色工作区。第一步中首页和报销批次可用，其他页面以清晰的“后续实现”占位显示，避免伪装为已完成功能。

首页的重点是下一步行动：显示当前批次数、物品数，以及“创建第一个报销批次”的入口。批次页提供“新建批次”按钮、名称输入对话框、刷新后的批次列表和空状态。创建操作经由 `BatchService`，UI 不直接调用 Repository 或编写 SQL。

## 视觉与交互

界面使用工作台风格：墨绿色导航、暖白内容背景、深灰正文与琥珀色行动按钮。卡片保持大间距、圆角和轻微边框；完整状态颜色保留给后续材料功能。所有主要按钮有可读名称与键盘焦点，空状态明确说明接下来能做什么。

## 数据流与启动

应用启动时确保目录存在、运行 Alembic migration、初始化默认材料类型和默认模板，然后创建 `DatabaseManager` 与 `StoragePathService` 注入窗口。关闭窗口时释放数据库连接及日志。这样首次打开软件即可使用，无需用户另行运行迁移命令。

## 验收

- `python -m reimbursement_manager` 会显示主窗口。
- “新建批次”成功后，批次页立即显示新记录。
- 空数据库时，首页和批次页显示可理解的空状态。
- UI 测试以 `offscreen` 平台构造窗口；服务测试覆盖批次创建和空名称校验。
