# Attachment Removal Design

Task 17 adds `AttachmentService.remove_attachment(attachment_id)`. The operation keeps attachment deletion recoverable by moving an existing managed file to the archive-root `.trash` directory before deleting its SQLite row. It does not invoke FileService's permanent `delete_file` during normal removal. StoragePathService computes the trash destination as `.trash/{attachment_id}/{original-relative-path}`; the database primary key prevents collisions while retaining the original Batch and Item layout for manual inspection or a future restore feature.

The service owns one database transaction and an outer filesystem compensation guard. It first loads the Attachment, resolves its relative path, and checks whether a regular file exists. If so, it creates the trash parent and performs a same-filesystem MOVE. It then deletes and flushes the Attachment row. Once the transaction commits, the original path is gone, the record is gone, and the full file remains in `.trash`. If the source file was already manually removed, the service still deletes the stale database row and creates no trash file.

If the database flush or commit fails after the file move, the database transaction rolls back and the outer guard moves the file from trash back to the original path. A restoration failure raises `AttachmentRemovalRollbackError` with both the original and recovery errors rather than silently leaving ambiguous state. If moving to trash fails, no database mutation commits. Missing attachments raise `AttachmentNotFoundError`.

Alternatives were rejected: permanently unlinking the managed file violates the MVP recovery requirement, while using the Windows Recycle Bin requires a dependency and OS integration not needed in Phase 1. The implementation adds only a safe trash-path builder to StoragePathService; FileService continues to own directory creation and MOVE. Tests cover normal trash movement, missing-file record cleanup, missing attachment errors, and forced database-delete failure with successful restoration.
