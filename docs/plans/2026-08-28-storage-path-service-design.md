# Storage Path Service Design

Task 10 introduces `StoragePathService`, constructed with the configured `archive_root` and a `NamingService`. It only calculates and validates paths; it does not create directories, copy files, or query the database. Batch directories use `{YYYY-MM}_{batch_name}` and Item directories use `{sequence}_{item_name}`. Both user-controlled names are cleaned by NamingService, keeping all Windows component rules centralized instead of duplicating filename logic.

The database-facing attachment path is represented as a `PurePosixPath`, for example `2026-08_实验耗材报销/001_树莓派Zero2W/001_树莓派Zero2W_发票_01.pdf`. Forward slashes make the stored value stable and independent of the current Windows archive-root location. The service separately resolves this relative path to a native absolute `Path` beneath `archive_root`. Moving the archive only requires constructing the service with a new root; stored Attachment rows remain unchanged.

All externally supplied relative paths are treated as untrusted. Resolution rejects empty paths, absolute POSIX paths, Windows drive paths, UNC paths, empty segments, current-directory segments, and parent traversal. The final resolved path is checked to remain under the normalized archive root. Stored filenames must be a single already-safe component; separators, reserved names, illegal characters, and trailing Windows-invalid characters are rejected. This prevents a later file service from accidentally writing outside the archive.

Directory components default to at most 120 UTF-16 code units, including their date or sequence prefix. NamingService receives an optional component-length budget so truncation and Unicode behavior remain centralized. Alternatives were rejected: storing native absolute paths would break archive migration, while making StoragePathService accept ORM entities would unnecessarily couple file-path policy to SQLAlchemy. Tests cover canonical Chinese paths, sanitization and fallbacks, stable relative paths across roots, length limits, no implicit filesystem writes, and traversal rejection.
