# Naming Service Design

Task 9 introduces a pure `NamingService` responsible for every stored attachment filename. Its primary operation accepts an Item sequence number, Item name, material display name, file index, extension, and an optional collection of existing filenames. It returns the required `{sequence}_{item}_{material}_{index}.{ext}` format without reading or changing the filesystem. Keeping collision inputs explicit makes the service deterministic and straightforward to test; `StoragePathService` and `AttachmentService` can later supply names from the target directory.

Each user-controlled component is normalized to Unicode NFC, stripped of surrounding whitespace, and cleaned of Windows-invalid characters plus ASCII control characters. Repeated invalid characters become one underscore. Trailing spaces and periods are removed. Empty Item and material names receive readable Chinese fallbacks. Windows device names such as CON, PRN, AUX, NUL, COM1 through COM9, and LPT1 through LPT9 are prefixed with an underscore, including forms such as `CON.txt`. The extension is normalized separately, lowercased, limited to 16 UTF-16 code units, and must remain non-empty.

Generated filenames default to at most 240 UTF-16 code units, below both the Attachment model's 255-character field and the common Windows component ceiling. If necessary, the Item and material components share the available length budget while the numeric prefixes, suffix, and extension are preserved. UTF-16 measurement handles non-BMP Unicode consistently with Windows. A caller may configure a smaller limit for tests or deployment constraints.

Collision detection uses `casefold()` because Windows filenames are normally case-insensitive. If the requested index already exists, the service increments the index until it finds a free generated name, preserving the standard naming format instead of adding a second unrelated suffix. Alternatives that query a directory inside NamingService or append random hashes were rejected: filesystem access belongs in later services, and random names reduce readability. Tests cover the canonical Chinese result, illegal characters, empty and reserved names, Unicode normalization, extension handling, overlong names, validation, and case-insensitive collision resolution.
