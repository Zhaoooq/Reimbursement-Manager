# Phase 1 集成验收设计

## 背景

前 17 项任务已经分别覆盖了数据模型、模板快照、附件归档、完整性计算与回收站删除。本设计将这些模块放入同一条业务链路，确认它们协作时仍符合 Phase 1 的核心目标：系统能准确指出某个物品缺少哪些材料。

## 验收范围

### 业务主链路

1. 初始化空 SQLite 数据库并写入默认材料类型。
2. 创建默认“普通购物”模板、报销批次和“树莓派 Zero 2 W”物品。
3. 确认物品从模板获得四项独立材料要求。
4. 上传实物照片、支付截图、订单截图，确认完整度为 3/4，且仅缺发票。
5. 上传发票，确认完整度为 4/4。
6. 在归档目录外部删除发票文件，确认完整度回落为 3/4，且附件健康状态标为 `MISSING`。

### 失败与边界场景

- 不存在的源文件不创建附件记录或归档文件。
- 模拟目标目录没有写入权限时，不创建附件记录或半成品文件。
- 中文路径、Windows 非法字符及目标目录已有同名文件时，生成安全且不冲突的名称。
- 文件复制成功但数据库写入失败时，服务补偿删除刚复制的正式文件，不留下无记录附件。

## 测试边界

所有测试使用 pytest 的 `tmp_path` 和内存 SQLite 数据库；不访问 `data/app.db`，也不修改真实报销归档目录。Windows 上目录权限的行为并不稳定，因此写入拒绝通过注入的 `FileService.copy_file` 抛出 `PermissionError` 来确定性模拟。
