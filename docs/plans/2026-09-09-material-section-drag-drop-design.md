# 材料区域拖放附件设计

物品详情页中的每个材料区域都是独立拖放目标。用户把一个或多个本地文件拖入某个区域时，文件直接归入该区域代表的材料类型；原有“+ 添加附件”按钮继续保留。

拖放控件只负责 Qt 事件处理、提取本地文件路径和显示悬停高亮。实际导入仍逐个调用 `AttachmentService.add_attachment()`，因此文件类型验证、重复检测、自动命名、归档复制、数据库事务和失败清理继续由服务层负责。处理结束后只刷新一次物品详情，避免批量导入期间反复重建控件。

批量拖放允许部分成功：某个文件失败不会阻止后续文件。界面在全部处理完后汇总失败文件及原因；成功导入的文件保留。非本地 URL 和不包含文件的拖放不会被接受。

测试覆盖本地文件拖入、多文件归类、悬停状态清理、非本地 URL 拒绝，以及原有按钮上传回归。数据库模型和附件服务不修改。
