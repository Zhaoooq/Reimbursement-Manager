# 界面与操作逻辑评审

> 评审对象：报销材料管理器 0.2.5（PySide6 桌面端）
> 评审时间：2026-11-04
> 证据来源：`docs/ui-review/*.png`（真机 1360×860 渲染，含真实演示数据：3 个批次 / 8 个物品 / 16 个附件）
> 代码基线：`ui/windows/main_window.py`（3704 行）、`ui/styles/base.qss`（1252 行）、`ui/theme.py`

---

## 0. 结论先行

界面已经有统一的 iOS 浅色语言和令牌体系，问题不在"没设计"，而在**三件事**：

**① 口径不一致**——同一个"还缺东西"被算了三种数，三个页面给出三个答案。
`首页·待处理 = 4`，`待补材料 = 8`，`所有物品 = 8`。首页按"原始材料不齐"计数（`dashboard_service.py:60`），待补材料按"原始材料或提交材料任一不齐"计数且**不过滤状态**（`pending_materials_service.py:41`），于是已报销的物品也躺在"待补材料"里。

**② 层级过载**——所有信息都用同一种"白卡片 + 14px 灰字"表达，于是没有层级，只能靠用户自己数卡片。物品详情一屏出现 6 层容器、3 层描边嵌套、4 处重复陈述同一事实。

**③ 反馈缺失**——关键动作的状态变化、禁用原因、失败原因，全部藏在 tooltip 或模态弹窗里。用户看不到"我刚做完的那一步生效了没有"。

下面按你给的五个维度逐项列，每条都带**位置**和**改法**。

## 1. 视觉问题

### 1.1 视觉一致性

**双重标题。** 侧栏写"报销归档"（`main_window.py:840`），首页 H1 又写"报销归档"（`:3452`）。首屏最顶部 60px 用来重复产品名，而真正要看的内容被压到 200px 以下。改法：首页 H1 改为当前动作语境的标题（如"今天要处理 4 项"），产品名只留在侧栏；或直接取消首页 H1，把统计卡上移。

**同一状态两套颜色。** 徽章体系里 `已提交` 是蓝色 `#007AFF`（QSS:1200-1206），但首页统计卡 `已提交` 被标成 `semantic="secondary"` 走灰色（`main_window.py:3477`）。物品详情徽章 `收集中` 用警告黄，`可提交` 用绿，可 `itemDetailWorkflowBadge` 的**默认底色**也是黄（QSS:900-909）——"无状态"和"收集中"撞色。

**三种"查看"入口。** 首页卡片右上角是文本按钮`查看 ›`，所有物品表、批次表、待补材料表**只能双击**，批次详情表也是双击。同一个"进入详情"，三种触发方式，其中两种不可见。

**主按钮通胀。** 批次详情页同屏出现两个主色 CTA：`+ 新增物品` 和 `标记批次已提交`（截图 `02-batch-detail.png`）。"标记已提交"是流程动作，不该抢占"新增物品"的视觉权重；它应该是一个**状态条的右侧次级动作**。

**危险操作与普通操作同级。** `删除批次`、`删除物品` 是浅红描边按钮，贴在内容区右下角，和"导出"同一视觉层（截图 `02`、`07`）。没有分隔、没有说明、没有二次输入。

**字号没有模数。** QSS 里能数出 11 个字号：28 / 24 / 22 / 20 / 18 / 17 / 16 / 15 / 14 / 13 / 12。其中 22（状态值）和 20（金额）语义不明——两个都是"重要数字"，却差 2px。建议收敛成 5 档：`28 数字` / `24 页面标题` / `17 区块标题` / `14 正文` / `12 辅助`，中间档全部归并。

**图标语言不统一。** 侧栏用 `QStyle.StandardPixmap` 系统图标（`SP_ComputerIcon`、`SP_MessageBoxWarning`…，`:848-855`），是 Windows 原生风格，和 iOS 浅色卡片是两套语言；"待补材料"用警告三角，把"待办"误读成"出错了"。

### 1.2 布局层次

**首屏信息倒置。** 统计卡占 118px 高（`:3461`），每张卡里数字 28px、下方 44px 空白；而"待处理"列表每行 100px。结果：一屏只能看到 4 条待办，看不到全貌。改法：卡片压到 88px，数字与说明同排（数字左、说明右），把省下的高度给列表。

**卡片套卡片。** 物品详情的支付凭证区是 `页面 → 支付凭证卡 → 订单截图卡 → 缩略图卡`，材料区是 `页面 → 材料区卡 → 附件卡 → 缩略图卡`。三层 1px 描边 + 三种圆角（14/12/8）叠在一起，视觉噪声大于信息量。改法：中间层去掉边框，只用 `secondary_surface` 底色分组；描边只保留最外层。

**顶部占位过多。** 物品详情前 210px 被三块占满：标题行、"商家/订单号/所属批次"整条白卡（右半全空）、"报销状态"卡（徽章单独占一行）。改法：三块合成一条信息带——左侧标题+金额，右侧徽章+主按钮，第二行用 `平台 · 日期 · 订单号 · 批次` 一行灰字，高度可从 210px 收到 120px。

**表格容器撑满剩余高度。** 4 行数据下面留 300px 空白（`layout.addWidget(..., 1)`），且白底与卡片同色，看起来像"加载失败的空卡"。改法：表格高度按内容自适应（最大 60vh），底部补一条汇总栏（`共 8 个物品 · 合计 ¥3,005.30`），空白就有了用途。

**列头居中、内容左对齐。** 所有物品页：列头"金额"居中，单元格 `¥365.00` 左起；"报销状态"列头居中，徽章右贴边（截图 `04-items-filled.png`）。改法：`horizontalHeader().setDefaultAlignment(Qt.AlignLeft | Qt.AlignVCenter)`，数字列统一右对齐（表头也右对齐），徽章列居中。

### 1.3 间距与配色

**间距没有"组内/组间"区分。** 页面 `setSpacing(16)` 一以贯之（`:3449`），于是标题和副标题间距 16px（太远），副标题和统计卡也 16px（太近）。同一数值无法同时表达两种关系。建议：`标题组内 4 / 组间 20 / 卡内 16 / 卡内元素间 8`。

**卡内边距四套值。** `dashboardStatCard` 16/12，`materialSection` 16/14，`mergedPaymentResult` 12/12，`batchDetailOverview` 16/16。肉眼不易指出，但会让"同类卡片"看起来不齐。统一为 16/16，紧凑卡用 14/12。

**徽章被拉伸成横幅。** 材料区的"缺少材料"（`:2289-2293`）是 `QLabel` 直接 `addWidget` 到纵向布局，没有 alignment，于是拉满整行宽（截图 `07`）。徽章一旦拉宽就不再是徽章，变成提示条。改法：`addWidget(label, 0, Qt.AlignLeft)`，或改用带左色条的提示行。

**进度条读不出来。** 高 7px、底色 `#E5E5EA`、白卡上对比不足；更关键的是**数字在卡片顶部、进度条在卡片底部**，中间隔着一行"缺少：…"，二者失去关联（截图 `03`）。改法：数字和条放同一行（左数字、右百分比、条在下方 8px），或把百分比直接叠在条上。

**说明文字对比度偏低。** `#8E8E93`（`tertiary_text`）用在 12–13px 的说明/文件名上，白底对比约 3:1，低于 WCAG AA 的 4.5:1；项目里 `#6E6E73` 是达标的（约 5:1）。建议：12px 文字一律用 `#6E6E73`，`#8E8E93` 只用于 ≥14px 或纯装饰。

**绿色被用于"进度"而非"完成"。** 首页"提交材料"进度条是绿色（QSS:435），但绿色在本系统里同时表示"已报销/材料完整"。一个 1/3 的进度用成功色，语义冲突。建议进度条只用中性灰+主色，绿色只留给"完成"徽章。

### 1.4 可读性

**附件名硬截断。** 附件卡固定 224px（`:2323`），文件名直接裁切、无省略号、无 tooltip：`001_树莓派 Zero 2 W_实物图_`（截图 `06`）。改法：`QFontMetrics.elidedText(..., Qt.ElideMiddle)` + `setToolTip(完整名)`；文件名本身也可缩短（去掉重复的序号前缀）。

**表格单元格裁切无兜底。** 待补材料页最右列"最终支付截图"贴边被切（截图 `01-pending`），且 `ResizeToContents` 在窗口变窄时无处可去。改法：所有易长列 `setToolTip(全文)`，并给列设 `Minimum` 而非 `ResizeToContents`。

**`4 / 4✓` 这种写法读不出状态。** 所有物品表的"材料"列把勾号塞进数字里（截图 `04`），勾号和数字同色同字号。改法：数字归数字，完整用绿色小字"已齐"或独立徽章列。

**批次列表没有表头。** `batch_table.horizontalHeader().setVisible(False)`（`:1662`，测试 `tests/ui/test_main_window.py:808` 已把它固化）。猜意图是"少一行标题、列表更干净"，但代价是五列全部失去释义：`1 | 2026-08-30 | 1 | ¥0.00 | 收集中`。这是**新用户第一个卡点**——尤其"1 个物品"和"¥0.00"两列都是数字，无法自解释。二选一：恢复表头；或保留无表头但把行改成自解释格式 `2026-08-30 · 1 个物品 · ¥0.00`。

**两行副标题读成一段。** 待补材料页把静态说明和动态计数放在同字号同色相邻两行（`:1296-1303`）："集中处理仍缺材料或尚未准备好提交的物品 / 还有 8 个物品需要处理"。改法：说明句删掉（页面名已表达），只留 `还有 8 个物品需要处理`，并把它做成标题右侧的灰字。

**空态没有出口。** 搜索无结果、无批次、无物品，都只有一句描述 + 一个按钮，但**搜索无结果时没有"清空搜索"**。用户只能手动删字。

### 1.5 交互反馈

**表格"能点"这件事没有任何提示。** 上一次改动为了去掉单击后的淡蓝选中块和焦点细框，把四张表都设成 `NoSelection` + `NoFocus`（`:1326-1329`、`:1655-1658`）——这个取舍是对的，行 hover 底色还在（截图 `04-items-filled.png` 里鼠标所在行确实变灰）。但：光标仍是箭头、行尾没有"查看"、只挂 `cellDoubleClicked`、键盘完全到不了。用户要靠猜才知道双击能进详情。
建议：保留 `NoSelection`，补三样——行内光标改手型、行尾固定"查看 ›"、单击即打开（保留双击）。这样既不出现选中块，也不用猜。

**禁用按钮看起来是启用的。** `导出提交材料` 在提交材料 1/3 时应禁用（`:2011`），但 QSS 的 `#itemDetailExportButton` 只定义了常态样式、没有 `:disabled`（QSS:940-945），于是它依旧是蓝字浅蓝底。点击无反应、无提示——用户会认为"点坏了"。同类问题：`生成支付截图` 的禁用原因只在 tooltip（`:2155`）。

**工作流不可逆、两套模型。** 物品详情是**单按钮推进**（标记已提交 → 标记已报销 → 归档，`:2552-2563`），误点无法撤回；批次详情却是**两个并列按钮**，且**始终 enabled**（`:3145-3150`），可以直接把"收集中"的批次标成"已报销"。同一套业务，两种交互。

**结果反馈全靠模态弹窗。** 导出成功、备份成功都弹 `QMessageBox.information`（`:2676`、`:3338`、`:3346`），弹完就没了，不能"打开所在文件夹"，也没有页内留痕。

**确认框是英文按钮。** 删除附件/物品/批次用 `QMessageBox.question` 的 `Yes/No`（`:2481`、`:2522`、`:3181`），在中文界面里出现"Yes / No"，破坏一致性，也容易被误点。

**错误直接抛服务层原文。** 创建物品、保存模板失败时把 `str(error)` 塞进弹窗（`:484`、`:729`），用户看到的是异常类文本，且不知道是哪个字段错了。

**"刷新"语义只在一个页面。** 只有待补材料页有刷新按钮（`:1306`），其他页靠切换导航隐式刷新；点了刷新也没有任何反馈（数据没变时看起来像没生效）。

## 2. 操作流程梳理

### 2.1 现状主干（11 步）

```
新建批次 → 双击批次 → 新增物品（9 字段弹窗）→ 双击物品
   → 逐类上传附件（4 类 × 进入子区域）→ 拖入/选文件
   → 生成最终支付截图（在页面最下方，默认禁用）
   → 标记已提交（此时才校验并弹缺失清单）
   → 标记已报销 → 归档
   → 回批次 → 导出报销材料（选文件夹/ZIP）→ 再次校验 → 强制导出
```

### 2.2 冗余与断点

**① 双击是唯一入口（4 处）。** 没有"查看"按钮、没有 hover 提示、没有键盘路径。

**② 上传必须先进详情。** 列表页看到"缺发票"，得双击→滚动到发票区→点"+添加附件"，三次定位。

**③ 支付截图这一步是"隐藏的必经路"。** 材料 4/4 齐了，但没生成合并截图，`display_status` 判定 `submission_ready` 为假，状态仍是"收集中"（`workflow_display.py:25`，这是刻意设计：判断依据必须是提交包齐备，不能只看 4/4）。逻辑没错，但界面上呈现为：**左边写 4/4、右边写 1/3、徽章写收集中、首页"可提交"是 0**。四句话互相矛盾，用户第一反应是"数据坏了"。这是本次评审里最容易被误判为 bug 的体验缺陷。

**④ 同一份缺失清单校验三次。** 标记已提交时（`:2594`）、导出批次时（`:3354`）、单据导出时（`:2632`）。第一次出现时用户已经离开材料区，只能"确定→返回→再找"。

**⑤ 归档不闭环。** 物品能点"归档"，批次没有归档入口，物品归档后批次状态也不联动。

**⑥ 导出后没有下一步。** 成功弹窗只告知路径，不给"打开文件夹"。

### 2.3 建议流程（步数 11 → 8，功能不减）

```
新建批次 → 新建物品（分区表单，模板前置）
   → 物品行内看到"缺 2 项" + 行尾"去补齐 →"
   → 详情页顶部常显"提交包状态"条：还缺什么 / 下一步是什么
   → 材料区一次拖入多类（按文件名智能归类的扩展点，V1 不做）
   → 支付凭证区：条件满足时按钮高亮并给出"两张已就绪，可生成"
   → 顶部操作条：生成支付截图 / 标记已提交（一个主动作）
   → 批次页底部：导出（含缺失预览与"仍然导出"）
```

关键差异：**把"下一步做什么"从第 9 步提前到第 2 步**，用户不再需要靠状态色反推流程。

## 3. 状态与提示规范

### 3.1 状态口径（必须先统一，否则 UI 怎么改都别扭）

现状：`收集中 / 可提交 / 已提交 / 已报销 / 已归档` 五态，其中"可提交"是派生态（`workflow_display.py:25`），判定依据是**提交材料齐备**，不是原始材料齐备。于是出现"4/4 仍是收集中"。

建议把"收集中"拆开，让标签直接说明缺什么：

- **待补原始材料**：`collection.is_complete == False`
- **待生成支付凭证**：原始齐全，但 `submission` 缺合并截图
- **可提交**：`submission.is_ready == True` 且 `status == collecting`
- **已提交 / 已报销 / 已归档**：保持不变

这样首页四张卡才互斥、可相加，用户也能自己验算。

### 3.2 三个口径要统一

- **首页"待处理"** 应等于 **待补材料页行数**。当前 4 ≠ 8。
- **待补材料页** 应过滤掉 `submitted / reimbursed / archived`（已报销的东西不该出现在"待补"里）。
- **所有物品页** 是全集，作为底盘，不参与"待办"计数。

### 3.3 提示分级（替代"一律弹窗"）

- **L1 页内状态**（默认）：绿色/黄色结果条，3 秒自动消失，带一个动作（如"打开文件夹"）、可撤销。
- **L2 行内提示**（校验失败）：字段下方红字，聚焦到该字段，**不弹窗**。
- **L3 模态确认**（仅不可逆操作）：删除、强制导出、跳过完整性提交。按钮必须是中文动词（`取消` / `删除`），并说明后果（"附件将移入回收站，可恢复"）。
- **禁用控件**：一律改成"可点击 + 点击后说明原因"，或按钮旁常显一行灰字原因。禁用态必须有视觉差异（`opacity`/灰底灰字）。

## 4. 改进方案（分三批，功能不变）

### P0 · 呈现层修正（零行为变更，可当天完成）

1. 表头对齐统一（左对齐；数字右、徽章中）。
2. 附件名省略号 + tooltip；长列一律 tooltip 兜底。
3. 徽章不拉伸：所有状态类 `QLabel` 加 `AlignLeft`；徽章统一 24px 高、12px 字。
4. 字号收敛为 5 档；`tertiary_text` 只用于 ≥14px。
5. 物品详情去掉重复的 "0 / 4" 与 "0%" 并存；百分比并入数字行。
6. 材料区"可拖动…"提示只在空分区显示（现状每区都显示，4 区 8 行噪声）。
7. `导出提交材料` 补 `:disabled` 样式。
8. 删除确认改中文按钮 + 后果说明。
9. 顶部标题组间距 4 / 组间 20，卡内边距统一 16。

### P1 · 交互结构（功能等价，需改测试）

1. 批次表恢复表头（**需同步修改 `tests/ui/test_main_window.py:808`**）。
2. 表格单击即打开（保留双击），加 hover 高亮、手型光标、行尾"查看 ›"。
3. 状态口径统一：拆分"待生成支付凭证"，首页与待补材料页同源计数，待补材料过滤已提交/已报销。
4. 批次工作流按钮按状态只保留一个有效动作，并常显当前状态徽章。
5. 禁用按钮改为"可点 + 说明"，或旁边常显缺失清单。
6. 物品详情顶部三块合并为一条信息带。
